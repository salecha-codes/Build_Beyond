# Browser preview deployment

The production site is generated by `npm ci && npm run build`. `frontend/dist` contains the application, the actual ONNX model, local WASM runtime, offline content/audio and generated service worker. Its default relative base supports both a domain root and a repository subdirectory.

## Platform preview

On a platform with a working preview relay:

```sh
sites-preview start /workspace/Build_Beyond
```

The root `openai` script starts the Node host on port 4173. In this session, the CLI failed before application startup with `preview relay unavailable: No such file or directory (os error 2)`. No public platform URL was returned. The regular local host remains available through `npm start` on port 3000.

## GitHub Pages

The `gh-pages` branch is prepared from `frontend/dist` with a `.nojekyll` file. Enable GitHub Pages in repository **Settings → Pages → Build and deployment**: select **Deploy from a branch**, branch **gh-pages**, folder **/(root)**, then Save.

The expected site address after successful Pages publication is `https://salecha-codes.github.io/Build_Beyond/`. An expected address is not proof of a successful deployment; check the Pages deployment result before treating it as live.

The current environment blocks HTTPS CONNECT to `api.github.com` before authentication, so the Pages setting could not be enabled through its API here. No credentials were copied into source or deployment assets.

## Other static hosts

Deploy `frontend/dist` as the publish directory. All model/runtime/audio requests are same-origin. The browser needs HTTPS (or localhost) for model checksum verification, camera access and the offline service worker. No API keys, server database or photo-upload endpoint are required.
